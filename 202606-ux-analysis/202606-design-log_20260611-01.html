體驗中心 UX
設計決策紀錄 01

記錄從流程架構、視覺升級到使用者回饋的所有討論決策。本份紀錄為個人研究與分析成果，版本 v6。

流程架構 圓桌會議 場景選擇 分身總結 字體響應式 視覺風格 使用者回饋
01
流程架構討論
›
選定職能跟選擇場景分開，好不好？
✓ 好處
先確立身份再推薦，個人化感強
職能選定後可展示對應痛點
導覽狀態清楚，身份持續顯示
✗ 壞處
多一步驟就多一個流失點
強制分類可能造成摩擦
跨職能場景難以處理
最終處理
保留分開。但讓職能頁「值得停留」——選完職能後顯示對應痛點，CTA 文字帶入職能名稱（如「查看採購的推薦場景」）。
HTML 把 P1 拆成兩頁（歡迎大廳 + 選定職能），好不好？
✓ 好處
歡迎頁可全力做情緒鋪陳
降低第一眼認知負荷
✗ 壞處
多一次點擊，沒換來明顯價值
流失風險在此最高
PDF 規劃的痛點泡泡在 HTML 消失了
最終處理
合併為單一頁面。左側浮動痛點泡泡 + 背景圖，右側職能選卡，選完職能才出現 CTA 按鈕。
底部 step bar 跟 header 進度條有什麼不同？需要保留兩個嗎？
桌機同時有兩個內容完全相同的進度條，造成視覺困惑。Header 的 breadcrumb 是 sticky 的，永遠可見，已完全滿足需求。
最終處理
移除底部 step bar，保留 HUD breadcrumb。同步清除相關 CSS 與 JS。
02
圓桌會議頁（P4）
›
P4 的演示內容會由工程師放入，只需要保留框架。
清空所有 chat UI、分身頭像、建議回覆，以及對應的 CSS 和 JS（initRoundtable、addMsg、sendMsg、CHAT_SCRIPTS、SUGGESTIONS）。
最終處理
保留 #p4-demo-area（工程師填入區）和底部 #p4-footer（查看分身能力總結按鈕），加上完整交接註解，說明可取用的 state 變數。
03
選擇場景頁（P2）
›
主管規劃是兩張大卡。要怎麼凸顯「為 OO 推薦的場景」？用圖片還是文字？
圖片在 B2B 流程場景中解釋不了場景邏輯，維護成本也高。改用「情境卡片」，讓使用者「讀懂再點」而不是「點了才知道」。
最終處理
每張卡片包含：痛點情境句（左側藍邊引言框）、分身彩色標籤、箭頭按鈕。其他職能場景改為 filter chip 切換列，點選職能後顯示對應場景列表。
卡片幫我統一大小，最推薦標記拿掉。
最終處理
移除主次卡片差異與所有推薦徽章，兩張卡完全等寬等高，視覺語言中性。
有人提供了一份 UI 優化建議（情境標籤、KPI 指標、難度時長、進度條等），這些建議怎麼看？
✓ 採納：Hero 壓縮 ✓ 採納：分身標籤顏色系統 ✗ 拒絕：難度時長 ✗ 拒絕：完成人數進度條 ✗ 拒絕：emoji 情境標籤
難度時長與完成人數是遊戲化平台語言，不適合 B2B 企業決策工具。進度條誤導使用者以為需要「破關」。emoji 作為結構性圖示是設計反模式（無法用設計 token 控制）。
04
分身總結頁（P5）
›
「現況突破」和「分身能力」兩個 tab 不夠明顯，要怎麼處理？
Tab 的問題是發現性（discoverability）——使用者進來視線往下走，不會注意到頁面頂部的切換按鈕，一半的內容會被忽略。這個網站預設使用者自己觀看（非業務帶 demo），tab 隱藏內容的成本更高。
最終處理
移除 tab，改為三段垂直流程：① 你做到了什麼（深色橫幅）→ ② 突破了什麼（雷達圖 + 說明列）→ ③ 這場體驗用到的分身陣容（卡片格）→ 轉換區 CTA。
05
字體尺寸與響應式規則
›
字體規則怎麼設定？
第一版規則
全站 body 16px，p1-sub 20px（指定），HUD steps 16px，裝飾性元件（DM Mono eyebrow、圓圈縮寫）保持小字。
修訂為
說明型內文（情境說明、場景引言、分身說明、按鈕文字）改為 14px。標題與主要 CTA 保持 16px 以上。最小可接受值 14px，裝飾性文字除外。
1200px 以下怎麼處理左側懸浮痛點泡泡？
最終處理
＜1200px 時 .p1-pains 完全隱藏，內容區置中，背景圖淡化為 25% 透明度，職能格維持四欄（768px 以下改三欄，480px 以下改兩欄）。
06
視覺風格升級（P2 ～ P5）
›
主管預期心理是「DATA 3D 科技感 + 深紫空間感 + 乾淨 SaaS dashboard」，設計風格怎麼定？
方向定為「SaaS 結構 + 空間感科技感」：在清楚的 SaaS 框架裡，用格線底背景暗示空間深度，用品牌色發光暈染暗示科技能量。不使用全深色（太遊戲感），保持淺底。
實作細節
背景：40px 格線紋理 + 頂部品牌光暈 radial-gradient。
卡片：rgba(255,255,255,.82) + backdrop-filter:blur(12px) + 右上角光暈 ::after 偽元素。
職能 badge：雙層 glow ring（box-shadow 兩層）。
accent 條：box-shadow 橫向發光。
箭頭按鈕：品牌漸層 + glow shadow，hover 時加深。
P3 robot icon：三層紫色光圈。
P5 深色橫幅：三段漸層（深藍→品牌藍→亮藍）+ 頂部白色光暈裝飾。
07
使用者體驗回饋處理
›
P2 進來不知道「我是誰、我在哪、我要幹嘛」；錨點在頁面中間段。
根因是認知斷層，不是 scroll 位置問題。Sticky header 的職能 badge 太小太安靜，進頁面的第一眼視線不會去找它。跳頁的瞬間，使用者的短期記憶被清空了。
最終處理
在 p2-body 頂部加身份確認橋接列：「你是採購 → 選一個你想體驗的場景，點擊卡片進入」。三個元素同字級同字重（16px bold），僅以底線分隔，視覺輕量但定向清楚。與 sticky header 是疊加關係，不合併。
P5「3分鐘 vs 3天」對比感不夠，3天顏色被背景吃掉。
根因：兩個數字用同一顏色，做成了並列而非對比。需要有「贏家」和「輸家」的視覺語言，而不是兩個同等強調的東西。
最終處理
em-win（正面關鍵字）：#fff815 黃色 + 雙層發光 text-shadow。em-old（負面關鍵字）：白色 + 底線（text-underline-offset: 3px），「被看見但不發光」。全部 6 個場景的 headline 依語意重新標記贏家與輸家。
「這些分身你可以帶走」——是體驗中的分身還是買了才能用的分身？
根因：「帶走」是模糊動詞，使用者不知道需要採取什麼行動。需要說清楚這些卡片的身份。
最終處理
標題改為「這場體驗用到的分身陣容」。標題下補說明：「以下分身在你剛才的體驗中協同運作，每一個都可以單獨部署到你的企業。」同時回答「這是體驗中的分身」和「可以部署」兩個問題。
場景卡片不知道可以點擊進去。
卡片缺乏互動暗示，外觀像展示方塊，使用者需要猜測它是否可點。
最終處理
每張場景卡片底部加「點擊進入體驗 →」文字，預設 opacity:0，hover 時淡入顯示（transition .15s）。降低使用者猜測成本。
