01
背景與設計目標
Context
›
產品定義

鼎新 AI 分身體驗中心是一個自助式互動體驗平台，讓企業使用者（製造業管理人員、職能主管）透過選擇自己的職能與工作場景，體驗 AI 分身如何在關鍵決策時刻替代人工協同——減少跨部門溝通等待，直接進行決策討論與建議輸出。

使用者來自廣告或其他商品頁導流，進入後獨立完成體驗，不依賴業務陪同。每個元件都必須能自我解釋，不能依賴人工說明。

GA 數據基準（v2.0 會議確認）

最大流失點在「進入體驗 → 選擇角色」，流失了 72%。使用者願意看（停留 6.5 分鐘），但流程認知門檻讓他們中途放棄。問題不在內容吸引力，在引導與操作清晰度。

關鍵洞察
平均停留 6.5 分鐘，完成率只有 12%。使用者願意看，但流程讓他們在中途放棄。主管 PPT Slide 17 直接確認：「在『選擇角色』就遇到了最主要的流失。」
主管規劃目標（PPT Slide 20–24）
歡迎大廳 → 選定職能 → 選擇場景 → 場景開場 → 圓桌會議 → 分身總結 Step 1 Step 2 Step 3 Step 4 Step 5 結束 同時看見痛點 推薦+其他 三段式引導 雷達圖+CTA

核心要求：移除重複角色選擇、全程 HUD 定向、三段式文案套版、強化「3天→3分鐘」說服點、CTA 改為「索取方案」+「訂閱最新消息」。

✓ 改動

浮動痛點泡泡 ≥1200px 顯示；＜1200px 隱藏

對應目標
符合主管 Slide 20 動線簡化方向：移除重複選擇，讓使用者一次完成「我是誰」的定義。
底部 Step Bar 移除

HUD breadcrumb 已 sticky 全程可見，底部重複一條相同進度條造成視覺冗餘與使用者困惑。

最終處理
移除底部 step bar，保留 HUD breadcrumb。同步清除 updateStepBar、#stepBar 相關 CSS 與 JS。
GoBack 導覽 Bug 修正

原本 gotoPage() 每次都 push 頁碼進 history，重複進同一頁會堆疊，goBack() 需多按幾次才能退回。P3 → P2 的返回因此失效。

最終處理
gotoPage() 加 if(n !== prev) 才 push，同一頁不重複記錄。goBack() 改直接操作 DOM，不透過 gotoPage()，避免 history 再次增長。

04
P2：選擇場景頁
Scene Selection
›
情境卡片設計

原本場景以純文字列表呈現，使用者看不出「為什麼選這個場景」。改為情境卡片，讓使用者讀懂再點，而非點了才知道。每張卡片包含：分類路徑標籤、場景名稱、痛點情境句（左側藍邊引言框）、分身彩色標籤（各職能色）、箭頭。

對應目標
符合 Slide 20 選擇場景步驟：推薦場景放上方，其他職能場景以 filter chip 切換，不讓使用者一次面對過多選擇。
使用者回饋：身份確認橋接

回饋：「跳到 P2 後不知道我是誰、我在哪、我要幹嘛。」根因是跳頁瞬間短期記憶被清空，sticky header 的職能 badge 太小太安靜，第一眼看不到。

最終處理
p2-body 頂部加身份確認橋接列：「你是採購 → 選一個你想體驗的場景，點擊卡片進入」，三個元素同字級（16px bold），視覺輕量但定向清楚。與 sticky header 疊加，不取代。
使用者回饋：場景卡點擊提示

回饋：「不知道卡片可以點進去。」卡片缺乏互動暗示，外觀像展示方塊。

最終處理
每張卡片底部加「點擊進入體驗 →」，預設 opacity:0，hover 時淡入（transition .15s）。
05
P3：場景開場頁
Scene Intro
›
三段式文案架構（對應 PPT Slide 22 + Excel）

依主管 PPT Slide 22，場景開場統一三段式結構，對應 Excel 三欄文案：

段落 ①
情境痛點（紅色左邊線區塊）：衝擊感切入，使用者感受「這就是我的問題」。
段落 ②
小秘書引導（glass 卡片，含分身 avatar 置中）：說明哪些分身參與、能做什麼。
整合調整
原本第三段「引導文案」與第二段重複（「不用從零訓練」說了兩遍）。整合進第二段 glass 卡片，刪除重複語彙，CTA 直接接在卡片底部，移除獨立的第三段容器。
移除 eyebrow 標籤

原本頁面頂部有「STEP 3 — 帶入數智分身」eyebrow，說廢話且重複 HUD 已顯示的步驟資訊。移除後改用場景名稱的 DM Mono 小標籤。

07
P5：分身總結頁
Summary & CTA
›
Tab 改為垂直流程

原本「現況突破」與「分身能力」兩個 tab，測試發現使用者不會主動點 tab，一半內容永遠被忽略。自助體驗的 discoverability 問題更嚴重。

最終處理
移除 tab，改為三段垂直流程：① 你做到了什麼（深色橫幅）→ ② 突破了什麼（雷達圖 + 說明列）→ ③ 這場體驗用到的分身陣容（卡片格）→ 轉換區 CTA。
使用者回饋：「3 天 vs 3 分鐘」對比感（對應 PPT Slide 23）

回饋：「3 天和 3 分鐘對比感不夠，顏色被背景吃掉。」根因是兩個數字用同一顏色，做成了並列而非對比。

最終處理
em-win（正面）：#fff815 黃色 + 雙層發光 text-shadow。em-old（負面）：白色 + 底線（text-underline-offset: 3px），「被看見但不發光」。眼睛先被黃色吸引看到好結果，再注意到帶底線的舊世界，形成自然的 before/after 閱讀節奏。
使用者回饋：分身卡片語意釐清

回饋：「這些分身是體驗中的角色設定，還是我買了才能用的產品？」

最終處理
標題改為「這場體驗用到的分身陣容」，補說明：「以下分身在你剛才的體驗中協同運作，每一個都可以單獨部署到你的企業。」同時回答兩個問題。
08
視覺設計系統升級
Visual Design
›
設計風格方向

主管預期：「DATA 3D 科技感 + 深紫空間感 + 乾淨 SaaS dashboard」。定調為 SaaS 結構 + 空間感科技感——清楚的資訊層級框架裡，用格線底暗示空間深度、品牌色發光暈染暗示科技能量，不採全深色（過於遊戲感）。

P2–P5 背景圖層
格線底
40px 格線紋理（rgba 3.5%）+ 頂部 radial-gradient 光暈，頁面有空間深度。
#scene-bg 方案
品牌背景圖改為獨立 position:fixed 的 div，不隨頁面切換重建，解決切換時背景閃爍問題。P1 顯示 bg-01，P2–P5 顯示 bg-02，透過 JS classList.toggle 切換。
Glass 卡片系統

所有卡片統一：rgba(255,255,255,.82) + backdrop-filter:blur(12px) + 右上角 ::after 光暈偽元素，hover 時光暈加深、卡片上移 4px。從「平面白框」升級為「浮動玻璃板」。
