01
需求方回饋 — 三大修正方向
v8 起點
›
背景

v7 示意版提交需求方確認後，收到三個主要修正方向，作為 v8 的執行依據。

01
P3
啟動分身頁面保留職能選擇介面，並設計樣式
P3 對話頁面需保留「選擇體驗職能視角」的介面，讓使用者在進入場景前可以明確選擇自己的視角。
02
HUD
將正在體驗的場景資訊放入 Header
HUD 目前只顯示職能，需加入「場景：OOO」讓使用者整個體驗過程都知道自己在哪個場景。
03
全站
融入產品介紹頁的體驗環節介面樣式
需求方有既有產品介紹頁，希望體驗中心的設計語言與其保持一致。
02
主管討論決策
設計決策
›
P2 職能視角切換 — 方案 D 確認

需求方希望在 P2 看到場景後，還能切換到不同職能視角體驗同一場景。討論過三個方案後確認採用方案 D。

方案 A
場景卡加第三個「換個視角」按鈕 — 不採用，三個按鈕 CTA 層級混亂
方案 B
Hover 時出現「以其他職能體驗」連結 — 不採用，行動裝置無法觸發
方案 C
場景 Agent Tag 可點擊直接切換 — 視覺提示不夠清楚，放棄
方案 D ✓
點「開始體驗」→ Modal 彈出「選擇體驗視角」→ 確認後進 P3。職能選項為場景參與職能（不列全部），目前選的職能排第一且預設選中。
P4 設計定位確認
確認
P4 中間區域由需求方內嵌，設計方不干涉。示意版先打「OOO 場景示意」文字佔位。HUD 新增「場景：OOO」tag，P3 後才顯示。
P5 右下角 Widget — 需求方要求
確認
需求方要求 P5 完成後出現右下角提示視窗（非設計方主動提案）。三張卡片依序跳出：完成通知、進度 + 進度條、推薦場景。10 秒後收合為 AI 頭像，hover 顯示「可以點開看訊息」。

HUD

HUD

P2 選擇場景
P2-1
P2
「開始體驗」→ 職能視角選擇 Modal（方案 D）
場景卡「開始體驗」按鈕點擊後，先彈出 vpModal，列出目前職能（預設選中）+ 場景其他職能，確認後才進 P3。選不同職能存入 state.viewpointRole，不覆蓋 state.role。

P3 體驗開場
P3-1
P3
對話氣泡樣式重構
使用者氣泡：深綠色 #1B6035，右側圓形頭像（職能首字），border-radius 16px 3px 16px 16px（右上角尖角朝頭像）。AI 氣泡：白底細邊框，左側品牌藍圓形 AI 頭像，border-radius 3px 16px 16px 16px。
P3-2
P3
對話逐條動態顯示 + 打字動畫
4 則對話依序出現，AI 回覆前先顯示三點打字動畫（typingBounce）。每則訊息有 fadeUp 淡入（opacity + translateY），AI 最後一句說完後才觸發分身上線。
P3-3
P3
Teaser 提示文字（對話結束後顯示）
AI 最後一句顯示完 300ms 後，在分身召集區上方淡入低調灰色小字「不用再到處拉人開會討論…」，告知使用者接下來的體驗意義。900ms 後觸發分身上線動畫。
P3-4
P3
分身 Avatar 硬幣翻面上線動畫
分身頭像一開始 offline（灰色 + grayscale），對話結束後逐個觸發 coinFlip keyframe（rotateY 0→90→0），翻面 275ms 時移除 offline class 變回職能色，同步加上右上角綠色燈號（::after 偽元素，dotPop 彈跳動畫）。
P3-5
P3
整頁 height:calc(100vh - HUD) 不超出一個畫面
p3-inner 固定為一個畫面高度，對話視窗 flex:1 撐滿中間空間，超出才滾動（overflow-y:auto），分身召集和 CTA 用 flex-shrink:0 固定在底部。

P4

P4
