ASSUMPTION VERIFIED

v1.0 假設確認結果

受眾是誰？
確認：新舊客戶都有，核心聚焦「企業使用者（經理人或員工）」，在工作上有實際工作流程與痛點的人。這個體驗中心不是第一個接觸點，正常邏輯是先經過 Landing Page 了解「數字分身」世界觀，再來這裡試玩。目前直接打廣告導流是「本末倒置」，是已知問題。
✓ 確認：潛在客戶為主補充：企業使用者（有工作痛點）
體驗後的 CTA 是什麼？
確認：「索取方案」＋「訂閱最新消息」兩個。下半年 KPI 定在「讓使用者完成體驗」，留資率不是主要目標。原本的「前往訂閱」定義不清，確認改掉。
✓ 確認：轉換節點設計方向正確
自助體驗還是業務陪同？
確認：自助體驗為主，但平台同時也用於業務展示場合。這確認了「每個元件都必須能自我解釋」的設計標準，所有說明文字都不能依賴業務在旁解釋。
✓ 確認：自助體驗影響：互動說明標準必須更高
連續兩次選角色的問題怎麼解？
確認修改方向：中間四個次角色選項全部拿掉，選完職能直接進場景。主管原話：「本來想說讓他們有多點路徑選擇，現在改版就是要把它踩平。」
✓ 確認：簡化流程，移除重複選擇
產品內嵌畫面要不要動？
確認：完全不動。產品後台介面是線上系統，我們只負責「外框/外包容器」的 UI/UX。雙重捲動 BUG 屬於產品端問題，反應過但目前不在我們範圍內。
✓ 確認：範圍外BUG 已知，產品端負責
